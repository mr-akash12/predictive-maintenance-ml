# Power BI dashboard — AI4I observation analytics

## Data connection
1. Run `python -m src.database --init` from the project root.
2. Power BI Desktop: **Get data → Text/CSV**, select `data/processed/ai4i2020_clean.csv` (simplest route), then **Load**. Rename the Power Query table to `machine_observations`. The CSV uses the original human-readable column names; for the DAX measures below, rename those columns in Power Query to the SQL-style names listed in `sql/schema.sql` before loading.
3. Alternatively, use **Get data → ODBC** with an installed SQLite ODBC driver and select `data/processed/maintenance.db`, table `machine_observations`. SQLite/ODBC availability is dependent on local drivers; no driver is bundled.
4. Recommended route for reproducibility: export the SQLite table to CSV with SQLite tooling, then import that CSV. The table and columns then exactly match `measures.dax`.

## Recommended simple Power Query column mapping (original CSV)
`UDI` → `udi`; `Product ID` → `product_id`; `Type` → `product_type`; `Air temperature [K]` → `air_temperature_k`; `Process temperature [K]` → `process_temperature_k`; `Rotational speed [rpm]` → `rotational_speed_rpm`; `Torque [Nm]` → `torque_nm`; `Tool wear [min]` → `tool_wear_min`; `Machine failure` → `machine_failure`; `TWF` → `twf`; `HDF` → `hdf`; `PWF` → `pwf`; `OSF` → `osf`; `RNF` → `rnf`.

## DAX
Create **one measure at a time** from `measures.dax` using **Modeling → New measure**. Format `Failure Rate` as a percentage. DAX source is a collection of expressions, not an importable Power BI report.

## Single-table model
Use `machine_observations` alone; **no relationships** are needed. `udi` identifies records, not unique equipment. Do not add invented time intelligence or calendar tables.

## Recommended report pages
- **Overview:** cards for Total Observations, Failure Count, Failure Rate and Non-Failure Count; slicer for product_type.
- **Operating patterns:** clustered columns: product_type versus Failure Rate; scatter: rotational_speed_rpm versus torque_nm, colour by machine_failure; distribution of tool_wear_min.
- **Sensor profiling:** bar visuals for average air/process temperatures, rotational speed, torque, wear; include filters and counts to contextualise subgroup rates.

## Interpretation and caveats
These are observed **synthetic** classification labels, not real downtime events. An AI4I row is an observation, not necessarily one machine. Failure-mode columns can be used for *post-hoc descriptive* analytics but must never be fed into the classifier. Machine-failure probability scores are not in the SQL/CSV table; do not present this as a live predictive dashboard without a separate scored-output pipeline. Refresh after rerunning database preparation.

## Manual deliverable
Open Power BI Desktop and build/save a `.pbix` locally. The `.pbix` file is not generated by this Python project.
